
# Caepher

This is a simple CA-based crypto system inspired by the work of ontocubism:

- https://www.youtube.com/watch?v=_-uzY8nzpYE

It is currently in a toy state. 

The basic idea is that we use simple 1-D cellular automata as a public-private key system.
In order to do this, we:

## 1. Find a set of 1-to-1 CA rules of neighborhood N on a ring of length L.

We want 1-to-1 rules so that we can run them in reverse to decrypt the message. It's important not only that they are locally-
invertible within the size of their neighborhood N, but that they are also globally-invertible across this 1-D ring of length L,
the length of our cellular automaton.

As a matter of empirical investigation, I found that N=5 has a reasonable density of reversible rules on a number of different
ring sizes.

This task of finding revertible rules is carried out by the program in reverse.c, which can be run with `make generate-db`.
This program was generated by Chat GPT based on a python script a wrote. I take no credit or blame for the code within.
Results of the process are stored in data/reversible.csv for easy lookup during the encryption process.

## 2. Encrypt by applying some set of M rules to the input.

The basic idea of the encryption is that the larger the neighborhood, the more possible transition functions. The set of
transition rules on a CA of size L is 2^2^L. So with even modest L, a random CA rule would inutitively seem impossible to
brute force. (Below I will discuss some known potential hurdles to practical use for this system.)

When you compose two rules, you effectively add their neighborhoods together to get the required neighborhood of the resulting
CA rule. That means if you apply M rules of size N, you achieve a total neighborhood size of L = N*M.

In practice, we do not use the total neighborhood size. We choose a neighborhood size of L <= N * M with a reasonable set of
rules of neighborhood N=5 are globally-reversible on. By composing rules that are all gloablly-invertible on rings of size
L, we ensure that composing any number M of them will be invertible on rings of size L.

Because the encryption can only encrypt L bits at a time, it will chunk the input and iteratively encrypt and decrypt messages
in L-bit chunks.

We can treat the set of M rules that have been selected, along with the additional parameters for L and how many
times R you want to repeat the encryption process, as the private key for the scheme.

## 3. Generating the public key.

The public key is now the CA rule on a 1-D ring of size L that acts as the composition of all M rules that have been selected.
This will consist of a map of 2^L states, where each state represents a potential sequence of a ring of length L, and the
resulting bit represents whether the transiitoning cell should be a 1 or 0.

I have found that a CA of length L=15 gives a reasonably sized key (32KB) and has a pretty decent density of reversible rules
of neighborhood N=5. We need a large neouhg sample of rules so that composing them multiple times will eventually lead to
enough combinations of reversible rules that cannot be brute forced. More discussion on that below.

## 4. Decrypting the Message.

Since each N=5 rule is 1-to-1, a full lookup table of the rule is only 2^5=32 bits (as opposed to 2^2^5 bits=4GB). So we can proceed inverting the application of our M rules by looking up the previous value from those M tables.

## Some Thoughts About Security

The basic security of the system comes from the repeated application of the N=5-bit rules. Out of a possible 2^2^5 (4,294,967,296) rules, I only found 400 rreversible ones by brute force search. So the strength of the encryption comes from:

1. The 400^M different combinations of rules. This means that the strength of the scheme is stringly tied to the number of rules applied.
2. The inherent difficulty of calculating the composed result of those M rules. To a rough appromization this is equivalent to calculating
    the lookup table which is M*2^L.

So the total cost with the parameters I've found expedient is approximately O(M * 2^L * 400^M).

In order to achieve 128-bit security, at L=15, we need M approx 48, which takes a very short period to generate keys, encode and decode data in the C application.

This all assumes that there is no shortcut to extract the N=5 rules somehow from the public key, or that the public key
could not be used to efficiently construct a reverse mapping.
